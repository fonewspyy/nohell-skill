## การตัดสินใจที่ต้องเลือกเอง

| เรื่อง | เลือก | เหตุผล |
|---|---|---|
| ratchet ต้องมี baseline ไหม | **โหมด diff-only ไม่ต้องมี** | hit บนบรรทัดที่ "เพิ่ม" คือของใหม่โดยนิยาม ⇒ diff-only **คือ** ratchet อยู่แล้ว (`mode: ratchet` = ห้ามเพิ่ม ไม่ใช่ห้ามมี) `--full --baseline` เก็บไว้ทำ baseline ตามที่ yaml ประกาศ |
| กฎ `kind: cmd` (13 ข้อ) | **ไม่รัน** | `detect.run` เรียกของนอก (`eslint`, `gitleaks`, `pnpm audit`, และ `nohell` CLI ที่ยังไม่มี) การรันคำสั่งจากคอนฟิกเป็นทางเปิดให้ arbitrary execution และไม่เข้ากับ diff-only — รายงานว่าไม่ได้ตรวจแทน |
| กฎ `multiline: true` (2 ข้อ) ในโหมด diff-only | **สแกนทั้งไฟล์ที่ถูกแก้** | pattern ข้ามบรรทัดจับใน "บรรทัดที่เพิ่ม" ที่ถูกตัดขาดไม่ได้ · over-report ตามปรัชญาที่หัว yaml เขียนไว้เอง (false positive ถูกกว่า false negative) ดีกว่าเงียบ |
| pyyaml ไม่ใช่ stdlib และ `python3` บนเครื่องนี้ไม่มี | **require แล้ว fail ดัง** | เขียน YAML parser เองคือ reinvent library ที่ ponytail ห้าม และ parser ที่ผิดเงียบ = บั๊กที่เฟสนี้ตั้งใจกัน · CI ต้องติดตั้ง pyyaml ให้ชัดใน workflow |

## ASSUMPTIONS

| ข้อสมมติ | เทสที่เฝ้ามันอยู่ |
|---|---|
| PCRE2 มีจริงตอนรัน | เช็ค `rg --version` หา `+pcre2` แล้ว exit 2 ถ้าไม่มี — ห้ามข้ามเงียบ (บทเรียนที่ HANDOFF เขียนไว้เอง) |
| ทุกกฎ regex compile ผ่านด้วย flag ที่ตัวเองประกาศ | runner ถือ exit 2 ของ `rg` เป็นความล้มเหลว ไม่ใช่ "ไม่เจอ" |
| `git diff` หาบรรทัดที่เพิ่มได้ถูก | เคสเทส ≥5 ที่รู้คำตอบ |

## ของที่ต้องมีตอนปิดงาน (checklist)

- [ ] เคสเทสของ runner ≥5 ที่รู้คำตอบ พร้อม exit code
- [ ] รันบน repo นี้เองแล้วอธิบายผลได้
- [ ] เอกสารการใช้ ~20 บรรทัดใน README ทั้งสองภาษา
- [ ] `validate.yml` รัน diff-only บน PR ของ repo นี้เอง
- [ ] รายงานบอกจำนวนกฎที่ **ไม่ได้** ตรวจทุกครั้ง

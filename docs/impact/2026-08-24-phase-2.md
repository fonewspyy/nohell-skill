## ของที่ขาด พร้อมหลักฐาน

| ขาด | หลักฐานที่รันจริง | ผลกับเฟสนี้ |
|---|---|---|
| `NOHELL-REPO-HANDOFF.md` | `ls` → No such file · `git log --all --diff-filter=A -- '*HANDOFF*'` → ว่าง | ภารกิจบอกว่า "ตัวเลขทั้งหมดในไฟล์นี้อ้างจากที่นั่น" ⇒ ไม่มีที่มาของบั๊ก 40 ข้อ |

| API key | `printenv ANTHROPIC_API_KEY` ฯลฯ → ไม่มีทั้งสี่ตัว | รัน eval และ commit `eval/baseline.json` ไม่ได้ |

## การตัดสินใจที่ทำได้เลย (Phase 2 ข้อ 4 อนุญาต research ไว้)

**ใช้ promptfoo ไม่เขียน `run.py` เอง** — ภารกิจสั่งว่า *"อย่าเขียนเอง ถ้าของสำเร็จรูปพอ — ponytail"*
ตรวจสเปกแล้วมีของที่ D4 ต้องการครบ:

| D4 ต้องการ | promptfoo ให้ |
|---|---|
| exact match ของ ID | `contains-all` รับ array ของค่าที่ต้องเจอครบ |
| recall / false-alarm / must-ask hit rate | JavaScript assertion คืน `GradingResult` และตั้งชื่อ metric เพื่อรวมยอดได้ |
| รัน 3 รอบ + รายงาน variance | `--repeat 3` และต้องใส่ `--no-cache` ไม่งั้นรอบ 2-3 กินแคช ไม่ได้ยิงจริง |

⚠️ `--repeat` ใช้แคชแยกต่อรอบ **ถ้าไม่ใส่ `--no-cache` variance จะออกมาเป็น 0 หลอก** — ข้อนี้ต้องเขียนลงเอกสารการใช้

## ASSUMPTIONS

| ข้อสมมติ | เทสที่เฝ้ามันอยู่ |
|---|---|
| ID ในเคสยังมีอยู่จริงในแคตตาล็อก | `validate-catalog.sh` check 7 (ID ที่ docs อ้างแต่ไม่มีจริง) จะจับให้เอง เพราะ `eval/` อยู่ใต้ scope ที่มันสแกน |
| เคสสะอาด ≥10 ต้องได้ผลว่าง | เป็นเทสในตัวเอง — ถ้าจับอะไรได้แปลว่า false alarm |

## ขอบเขต — สิ่งที่ **ไม่** ทำในเฟสนี้

เขียน runner ของ `hell-rules.yaml` (Phase 3) · เพิ่มเนื้อหาหมวดใหม่ (Phase 4) · แตะ `skills/**`
**และไม่แต่งเคสขึ้นเอง** — golden set ที่ไม่ได้มาจากบั๊กจริงคือ baseline ที่วัดอะไรไม่ได้
ซึ่งตรงหมวด `MEAS` ของแคตตาล็อกตัวเอง (การวัดที่เชื่อไม่ได้)

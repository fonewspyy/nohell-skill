## `NOHELL-REPO-HANDOFF.md` ไม่มีอยู่จริง — และไม่จำเป็นแล้ว

| หลักฐานที่รันจริง | ผล |
|---|---|
| `ls NOHELL-REPO-HANDOFF.md` → No such file | ไฟล์ไม่มีในรีโป |
| `git log --all --diff-filter=A -- '*HANDOFF*'` → ว่าง | **ไม่เคยมีในประวัติ** ไม่ใช่ถูกลบ |
| `grep -rn '19 ข้อ\|21 ข้อ\|repo A\|repo B'` | เจอแต่การ*อ้างถึง* ไม่มีตัวรายการ ตรงกับ `BACKLOG` B8 ที่เขียนไว้เองว่า *"ไม่มีที่ไหนบันทึกว่ากฎไหนเคย fire จริงบน repo ไหน"* |

แต่บั๊กที่ HANDOFF จะอ้างถึงคือบั๊กของ repo A ซึ่ง**ยังอยู่ครบในคลังบันทึกของ repo นั้นเอง**
จึงสร้าง golden set จากต้นทางโดยตรง ไม่ต้องผ่าน HANDOFF — ดีกว่าเดิมด้วยเพราะบันทึกมี
root cause กับตัวเลขที่วัดไว้ ไม่ใช่แค่รายการ ID

## การตัดสินใจ: เขียน `run.py` เอง ไม่ใช้ promptfoo (ข้อ 4 อนุญาต research ไว้)

ภารกิจสั่งว่า *"อย่าเขียนเอง ถ้าของสำเร็จรูปพอ — ponytail"* จึง**วัดก่อนตัดสิน** ไม่เดา

| D4 ต้องการ | promptfoo ให้ | สรุป |
|---|---|---|
| exact match ของ ID | `contains-all` | พอ |
| recall / false-alarm / must-ask | JavaScript assertion + named metric | พอ |
| 3 รอบ + variance | `--repeat 3` (ต้องคู่ `--no-cache` ไม่งั้นรอบ 2-3 กินแคช variance เป็น 0 หลอก) | พอ |

**ความสามารถพอจริงทั้งสามข้อ** แต่ต้นทุนที่วัดได้คือ

```
npx --yes promptfoo@latest --version   →  4 นาที 18 วินาที + deprecated deps
```

repo นี้มี JS dependency **ศูนย์ตัว** และ CI รันจบในไม่กี่วินาที เทียบกับ stdlib ~130 บรรทัด
ที่เรียก CLI ซึ่งมีอยู่แล้วบนเครื่อง — ponytail ถามว่าอันไหน*ซับซ้อนรวมน้อยกว่า* ไม่ใช่อันไหน
พิมพ์น้อยกว่า จึงเลือกเขียนเอง และบันทึกตัวเลขนี้ไว้ให้ค้านได้
